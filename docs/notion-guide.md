# Notion 학습 기록 가이드

메인 대화가 단계가 끝날 때마다 Notion에 학습 기록을 남긴다. 대화 내용(사용자 질문, 트러블슈팅)이 필요하므로 서브에이전트에 맡기지 않는다.

## 위치
- 상위 페이지 "바이브 코딩": https://app.notion.com/p/40b4115beefb815dbc1dd0033d060d93
- 그 안의 "학습 리뷰" 데이터베이스: collection://1121b459-f685-4a8c-9525-f0efade5bbc5

## 구조: 큰 기능(파트)마다 카드 하나
- 카드는 S0, S1, S2, ... 처럼 큰 기능마다 하나. 단계(S2-a 등)마다 카드를 만들지 않는다.
- 카드 속성: 제목, 번호(파트 순서), 단계(예: "S3 (S3-a ~ ...)"), 태그, 한 줄 요약. 날짜는 쓰지 않는다.
- 카드 본문: 📌 파트 요약(회색 콜아웃) → 🗺 단계 한눈에 보기(단계 | 한 줄 요약 표) → 📂 단계별 기록
- 각 단계 기록은 카드 안의 **하위 페이지**로 만든다.

## 단계가 끝나면
1. 해당 파트 카드 안에 단계 하위 페이지를 만든다. 새 파트면 카드부터 만든다.
2. 카드의 "단계 한눈에 보기" 표에 그 단계 줄을 추가하고, 필요하면 태그·한 줄 요약을 넓힌다.
3. 상위 페이지 "진행 현황"은 큰 파트만 한 줄씩 적는다(괄호에 한 것/남은 것). 단계는 적지 않는다. 파트 안의 단계가 모두 끝나야 체크한다.
4. 아키텍처가 바뀌면 상위 페이지의 mermaid 다이어그램도 고친다.

## 단계 하위 페이지 본문 (순서대로)
1. 📌 한 줄 요약 (회색 콜아웃)
2. 목차
3. 🧠 이번에 배운 개념 — 쉬운 비유, 표
4. ❓ 내가 헷갈렸던 질문과 답 — 사용자가 실제로 한 질문마다 토글 하나
5. 🤔 왜 이 기술을 썼나 — 선택 | 대안 | 고른 이유 표 + 면접 답변 한 문단(콜아웃). 면접에서 중요해서 필수
6. 🛠 프로젝트에 이렇게 적용했다 — 결정 | 이유 표 + 트러블슈팅(노란 콜아웃: 문제/원인/해결/결과)
7. 💼 예상 질문 — 토글, 답은 면접 존댓말
8. 🔗 다음에 볼 것

## 주의
- 셸 명령어는 넣지 않는다. 이모지·색은 최소로, 짧게 쓴다.
- 서버 IP, 계정 ID, DB 사용자명·비밀번호는 절대 쓰지 않는다.
- 이 파트 묶음 방식은 Notion에만 적용한다. backlog·CLAUDE.md·에이전트 구조는 바꾸지 않는다.
